CASE FILE №01 — COMMISSIONED WORK

BATTLEGROUNDS
COMBAT SYSTEM

The one I'm proudest of — a full PvP fighting-game combat core built for a battlegrounds-style client project.

Fist-to-fist combat with a real reason to play carefully: a tracked 4-hit combo that only unlocks its airborne finisher after landing hits on the same opponent back-to-back, an 8-directional dash with its own anti-escape rules, guard-break, hitstop, pop-knockback, a from-scratch ragdoll on death, and three AI training dummies built so combos and defense can both be tested solo.

Architecture
The client fires plain intents — M1, Heavy, Downslam, Block, Dash — and the server owns every bit of timing, hitbox resolution, and combo state, exactly the same non-negotiable split as the sword system below, just running a faster, punchier fighting-game loop instead of a duel.
Combo tracking
The finisher isn't just "press M1 four times in the air." The server tracks which specific opponent the last confirmed hits actually landed on, with its own expiry window, so the airborne Downslam only unlocks after a real, unbroken combo on that same target — not four whiffed swings near a crowd.
Anti-escape
Landing any hit locks the target's dash for 0.8 seconds, closing the obvious "get combo'd, instantly dash away" exploit. Guard-break does the same for blocking, but re-locks it for the stun duration plus a grace period afterward — a broken guard can't be thrown back up the instant the stun ends.
Hit feel
Every attack carries its own hitstop — a brief freeze on whatever animation is currently playing, combat or not — plus a small instant "pop" knockback layered underneath the real knockback. That's the frame-level texture that makes a hit actually read as a hit instead of a number going down.
Whiff punish
Missing the Downslam finisher self-stuns the attacker. Committing to the big swing is a real risk, not a free option to throw out on cooldown.
Ragdoll & training rig
Death triggers a ragdoll built from scratch — the character is cloned, stripped of scripts and rigid welds, and rebuilt with a BallSocketConstraint per limb plus a physics-safe invisible collision proxy, while the original corpse is force-hidden every frame and the camera hands off to the ragdoll's head. Three distinct AI dummy types — an idle punching bag, an active blocker with its own stamina pool, and a dummy that swings back — let combo and defense testing happen without a second player in the server.
CASE FILE №02 — COMMISSIONED WORK

SWORD COMBAT
SYSTEM

A Souls-like combat framework built to spec for a client, from empty scene to a fully validated hit.

The client asked for combat that feels like Elden Ring, not Roblox's usual touch-to-damage tools. What shipped is a full server-authoritative combat loop — stamina and posture, block and parry, guard-break, i-frame dodges, a slope-aware slide, and lock-on targeting — plus a second, animation-free procedural swing engine built by reverse-engineering the rig's own joints. The scene itself is a bare grey-box test arena; every system below is what the commission was actually about.

Architecture
The client predicts its own swing instantly for responsive feel; the server independently times windup / active / recovery, resolves hits with its own box-overlap query, and is the only thing that can actually apply damage. A hit the server didn't validate never happened — CombatServer owns timing, hitboxes, posture, stamina, and knockback outright.
Resource system
Stamina and posture run as separate economies: blocking drains stamina, every hit (blocked or not) chips posture, and either bottoming out triggers a guard-break stun and knockback independent of remaining health — the poise-break loop Souls-likes are built around.
Parry & feint
A short timed window on block start turns a well-timed hit into a full parry: the attacker's swing is cancelled, their posture is punished, and they're stunned. Attacks also carry their own feint window, so a read can be cancelled out of instead of committed blind.
Movement physics
Dodge and slide run on LinearVelocity + AlignOrientation constraints instead of Humanoid state hacks. i-frames open and close on a sub-frame timer independent of the animation; slide speed integrates real slope angle every frame, so it accelerates downhill and bleeds off on the flat or uphill.
Procedural swing engine
A second swing system needs no animation assets at all: it drives raw Motor6D poses through an eased pose timeline, complete with a "hitstop" gate that freezes the swing mid-motion until the server confirms a hit. Per-rig joint mapping for R6 and R15 was reverse-engineered by direct empirical testing, not assumed from docs — the rig's own axis conventions are documented in the config file itself.
Lock-on camera
Targets are scored by on-screen distance to center rather than raw world distance, so lock-on grabs whatever the player is already looking near, then smoothly homes the camera and character rotation onto it.
CASE FILE №03 — PERSONAL PROJECT, IN DEVELOPMENT

THE WAR
TABLE

Orbital grand strategy on a real, to-scale Earth — no avatar, no ground view, ever.

A Hearts of Iron-style grand strategy game commanded entirely from orbit. The map isn't a fictional continent — it's all 241 of today's real countries and territories, rebuilt from Natural Earth boundary data into 3,406 hand-triangulated provinces wrapped around a 1,000-stud sphere, with HOI4-style capitulation and victory-point mechanics layered on top of the real modern political map.

Data pipeline
Real Natural Earth admin-0/admin-1 boundary data runs through edge subdivision (so long borders follow the sphere instead of cutting a straight chord through it), gnomonic projection, earcut triangulation, and adaptive sag-correction subdivision — every province is a real polygon draped on the sphere, not a flat grid tile standing in for a coastline.
Engine-limit workarounds
Roblox caps live EditableMesh instances at roughly eight and — discovered the hard way — doesn't replicate server-built EditableMesh geometry to clients at all. The whole planet is packed into seven client-built batch meshes instead, with every province keeping its own solid color via per-face color IDs inside the shared mesh.
Picking without physics
Hover and click never touch a physics raycast. An analytic ray-sphere intersection plus a cheap bounding-cone reject and a spherical point-in-triangle test resolve exactly which of the 3,406 pieces the cursor is over — the only way to keep per-triangle province identity once everything is batched into a handful of meshes.
Camera
Arcball rotation is driven by absolute cursor position, not mouse delta, because delta reporting is frequently unreliable in this environment. Momentum decays smoothly after release, and a screen-edge-aware fallback keeps the planet spinning if the OS cursor leaves the viewport mid-drag.
Server authority
Province ownership lives entirely server-side and replicates out through dedicated RemoteEvents; clients only ever send intent, never state — the same rule the combat system runs on, applied to a strategy layer instead of a hitbox.
Setting
Modern-day political borders carry HOI4-style mechanics on top — capitulation at 80% victory-point loss rather than on capital fall, governments in exile that keep playing. Sixteen hand-picked nations carry WW2-era flavor identity layered over their real, current-day borders.
